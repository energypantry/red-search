### 1.2 入口与防护面

- **CDN/WAF**: `www` 走 TencentEdgeOne + `acw_tc` cookie；`edith` 走阿里 CDN（`x-cdn-xhssupplier: al`）。
- **网关签名门**: 无签名请求 →
  - POST `/api/sns/web/v1/homefeed` → **HTTP 406** `{"code":-1,"success":false}`，响应头 `access-control-allow-headers: f,x-s,x-sign,x-t`
  - GET 未签名 → **HTTP 500** `create invoker failed, service: jarvis-gateway-default`
- **必须请求头**: `X-s`、`X-t`、`X-S-Common`；可选 `X-Mns`、`Sc-T`、`X-Sign`、`x-b3-traceid`
- **笔记详情 token 门**: 直接访问 `/explore/<noteId>`（无有效 `xsec_token`）→ 302 →
  `/404/sec_xxx?...&error_code=300031&error_msg=当前笔记暂时无法浏览`
  → 笔记必须从搜索/feed 结果页由页面 JS 生成的新鲜 `xsec_token` 打开。
- **行为风控**: 现有工具实测——去掉键盘输入事件、改纯 URL 跳转会触发验证墙；连续 8 次搜索触发过一次连接断开。

### 1.4 签名机制（已逆向确证）

**算法链**（源码位置：`fe-static.xhscdn.com/.../js/vendor-dynamic.0d98fa0a.js`，webpack module `384` + module `4455`）：

```
webBuild      = "4.4.3"                 # w.i8
appVer        = "6.52.0"                # 硬编码
platform      = navigator.userAgentData.platform  → "Linux"（实测）

content       = path                    # GET
              | path + JSON.stringify(body)   # POST(object/array) / + string
x5            = MD5(content)            # ed.Pu
p             = MD5(path)               # ed.Pu(e)
x3            = window.mnsv2(content, x5, p)        # 核心签名器（非确定性，内含 nonce）
{ x6, x7 }    = buildEncSskSign(x5)     # localStorage ssk map + SHA1 + nonce

X-s payload   = { x0:webBuild, x1:"xhs-pc-web", x2:platform, x3, x4:typeof(body)|"", x5, x6, x7 }
X-s           = "XYS_" + customB64(utf8(JSON.stringify(payload)))

customB64 字母表 = "ZmserbBoHQtNP+wOcza/LpngG8yJq42KWYj0DSfdikx3VT16IlUAFM97hECvuRX5"

X-S-Common    = customB64(utf8(JSON.stringify({
                  s0: 4, s1: "", x0: 1, x1: "4.4.3", x2: "Linux", x3: "xhs-pc-web",
                  x4: "6.52.0", x5: <cookie a1 值>, x6:"", x7:"",
                  x8: <2032 字符本地指纹 blob>, x9: crc32(x8 等), x10: 签名计数,
                  x11: "normal", x12: "<ts>;<ts>"
                })))            # 实测长度 3032 字符
X-t           = 毫秒时间戳
```

**实测验证结果**：

| 断言 | 结果 | 证据 |
|---|---|---|
| `x5 = MD5(path [+ body])` | ✅ **12/21 真实请求命中** | 用真实抓包逐一反算 md5 比对 |
| `x3` 由 `window.mnsv2(content, x5, p)` 产生 | ✅ App 自身调用被钩子捕获，参数逐字一致 | 钩住 `window.mnsv2` 后重载页面，捕获 23 次调用 |
| `window.mnsv2` 全局可调用 | ✅ `typeof === "function"` | 页面内求值 |
| `window._webmsxyw` 仍存在（旧签名，返回 `XYW_` 前缀） | ✅ | 页面内求值，返回 `{"X-s":"XYW_..."}` |
| 自算 header 直接打 API 成功 | ❌ **未打通** | 见 §2 阻塞点 |

**关键阻塞点（已实测，非猜测）**：

1. **`x6/x7`（encSsk）无法离线重建** — 依赖 `localStorage` 中 ssk map + SHA1 nonce。
2. **`X-S-Common` 是 3KB 设备指纹** — 含 cookie `a1`、2032 字符 `x8` blob；缺少它时网关返回 500 `create invoker failed`。
3. **手动调 `mnsv2` 前缀不一致** — 自算得 `mns0301_*`，App 自身调用得 `mns0101_*`（同函数、同参数、同页面）；说明内部存在未对齐的状态/分支（疑似 signSvn 选择）。
4. 自算 `X-s` 长度 408，真实 556~564 —— 缺项即为 `x6/x7`。

→ **结论：「从零手搓完整头部」不可行；必须复用页面运行时状态。**

## 2. hypothesis_queue（路线排序）

### 路线 A — 浏览器 UI 自动化（**现状：已实现且可用**）

- 实现：`Agent Browser Runtime`（Docker 持久化 Chrome，已登录）+ `cli/brs.js` + `extractors/golddigger-xhs.extract.js`
- 入口：`~/.openclaw-vovo/workspace/tools/xiaohongshu/xhs.sh`（`setup|search|suggest|read|open|profile`）
- 优点：完全绕过签名（页面 JS 自己签）；已验证；无逆向维护成本
- 缺点：串行、慢（单次搜索 ~30s+）、需 GUI/容器、风控按行为计数
- 前置：Docker + 已登录 Chrome + 拟人节奏（间隔 ≥30s，保留键盘事件）
- 证伪条件：出现无法通过拟人节奏规避的验证墙
- **证据等级：已验证（今日实测 runtime `extensionConnected: true`，`/explore` 页 `note_items: 30`）**

### 路线 B — 页面内签名 + API 直呼（**推荐用于大批量/结构化**）

- 架构：长驻已登录页面作为「签名服务」；Node 侧持 cookie 发 API 请求；签名由页面运行时产出
- 两种实现：
  - **B1（稳）**：不在外部拼 header，而是复用页面里 App 自己的请求管道（webpack 内的 axios 实例 / 拦截器），由 App 自己完成签名 → 最不易碎
  - **B2（活）**：CDP 调用 `window.mnsv2` + 在页面内跑 `buildEncSskSign` 等价逻辑 + 持久化 localStorage 状态 → 即公开库 `ReaJason/xhs` 的 sign-server 模式
- 优点：吞吐远高于 UI 自动化；可拿结构化 JSON
- 缺点：需要维护签名服务；`mns0101/mns0301` 分支未完全对齐；页面态失效即全链路失效
- 前置：实现并验证 B1 或 B2；持久化 localStorage/指纹
- **证据等级：算法与参数已确证；端到端未打通（阻塞点见 §1.4）**

### 路线 C — 离线签名器（抽取 `signV2Init`）

- 实现：抽取 vendor bundle `module 4455` 的混淆 `signV2Init` blob + `mnsv2`，在 Node/jsdom 中执行
- 优点：无需浏览器
- 缺点：对抗性最强、最易碎（每次发版重来）；仍需移植设备指纹
- **证据等级：假设（本轮未验证抽取可行性）**

### 路线 D — 现成开源（需先验证时效性）

- 候选：`NanmiCoder/MediaCrawler`（64k★）、`cv-cat/Spider_XHS`（7.5k★）、`ReaJason/xhs`、`yangsijie666/xiaohongshu-crawler`（Playwright）
- 注意：小红书签名迭代频繁，star 数不代表当前可用
- **证据等级：仅检索级信息，未验证可用性 → 需单独做 validate-path**

### 路线 E — SSR / DOM 解析（低风险，适合公开数据）

- 依据：`/explore` 返回 HTML 含 `window.__INITIAL_STATE__`（实测含 30 条 feed）
- 适用：公开首页流、公开笔记页的静态字段
- 缺点：翻页/评论/搜索仍需 API；覆盖面窄
- **证据等级：部分验证（确认 `__INITIAL_STATE__` 存在及含 feed）**

## 3. 推荐

| 场景 | 路线 |
|---|---|
| 关键词调研 / 少量、需真人级隐蔽 | **A（现状够用）** |
| 大批量结构化采集（笔记+评论+用户） | **B1 > B2** |
| 公开数据的低成本抓取 | E |
| 研究与对照 | D（先验证时效） |

**不建议**：C（投入产出比最差，除非 B 被反复打断）。
