# 访问频次与风险判断

> 工程判断，非精确测量。依据来自 2026-09 的真实流量样本、实现对照与实测请求。

## 1. 目标侧能看到什么

| 维度 | 真机浏览器 | 本工具 | 差异风险 |
|---|---|---|---|
| `a1` / `web_session` | 真机登录态 | **同一个**（从浏览器取） | ✅ 无 |
| 出口 IP | 本机 | 本机 | ✅ 无 |
| `X-s` 算法 | 页面 JS | 纯算重实现 | 🟡 同构但非同一实现 |
| `X-S-Common` 设备指纹 | 出厂即固定，数月不变 | **可固定**（真机 pin）或持久化合成 | 🔴 见 §2 |
| 会话状态（pageLoadTs / sequence） | 稳定 + 递增 | 复用 `SessionManager` | ✅ 已对齐 |
| 页面加载前置序列 | 有（config → user/me → …） | 无 | 🟡 中 |
| 请求节奏 | 人类 | 节流 + 抖动 | 🟡 可调 |

## 2. 三个关键风险，按权重排序

### 🔴 R1 — 设备指纹不稳定（最大隐患）

`xhshow` **原生默认在每个签名请求里重新随机生成一整套设备指纹**（WebGL hash / Canvas hash / 屏幕分辨率 / GPU renderer / CPU 核心 / 内存 / plugins 全部随机）。

实测证据——同一 `a1` 连续三次调用，`x8`(760B blob) 的哈希：

```
dc8418b1   GPU=RTX 3070 Ti   屏幕=3840x2160
f9079a03   GPU=RTX 4080      屏幕=1600x900
89ba5abf   GPU=AMD RX 560    屏幕=1600x900
```

后果：服务端看到"**同一个账号、同一个 IP，每秒换一台新电脑**"。真实设备指纹是数月不变的，这是可以直接聚类的强异常。

**本项目已修复**：`resolve_fingerprint()` 把指纹固定下来（真机 pin 优先，否则持久化一份合成指纹，跨进程复用）。

### 🟡 R2 — 指纹与 `a1` 的绑定身份不一致

`a1` 是浏览器用**真机指纹**换来的。用 `synthetic` 模式时，工具自称一台 **Windows Edge + NVIDIA/AMD D3D11** 机器，而 `a1` 来自 **macOS Chrome**：

- 账号从 Mac 跳到 Windows → **跨平台换设备**（比同平台换机器更强的信号）
- 若不同步 UA，还会出现"HTTP 头说 Mac、指纹 `x1` 说 Windows"的**自相矛盾**（本项目已自动同步 UA 消除）

### 🟡 R3 — 缺少真实会话前置序列

真实会话是 `GET /v1/config` → `GET /v2/user/me` → `GET /v1/system/config` → … 才到业务请求。本工具直接打业务接口，是"无头请求"。单次无害，长期看是弱信号。

**未处理。** 需要的话可以在 `XhsClient` 里加一个 `warmup()`。

## 3. 概率估计

| 配置 | 低量（≤50 请求/天） | 中量（数百/天） | 批量（数千+/天） |
|---|---|---|---|
| 每请求随机指纹（xhshow 原生默认） | 🟠 中 | 🔴 高 | 🔴 极高 |
| 持久化合成指纹（与 `a1` 来源平台不一致） | 🟠 中 | 🟠 中高 | 🔴 高 |
| **pin 真机指纹**（与 `a1` 同源同平台同设备） | 🟢 低 | 🟢 低-中 | 🟡 中 |

**实测校准**：在指纹随机（最差情况）下连续打 ~20 次请求**全部 200**，说明**不是一碰就封**。但"同账号 N 台设备"的证据随请求数**线性累积**，量上去后命中概率陡增。

一句话：**短期低量几乎必过，长期大量必被关注。**

## 4. 指纹模式怎么选

| 模式 | 含义 | 适用 |
|---|---|---|
| `real`（有 pin 文件时 `auto` 的默认） | 用你登录的那个浏览器的真机 `x8` | ✅ **主号** |
| `synthetic` | 持久化合成指纹（自称 Windows Edge；UA 同步） | **副号 / 新号**；无浏览器的服务器 |
| `auto` | 有真机就用真机，否则用持久化合成 | 默认 |

```bash
xhs fp                                       # 抓真机指纹（切成 real）
XHS_FP_MODE=synthetic xhs search "咖啡" 20     # 临时用合成
```

**结论**：主号用 `real`。要长时间/大批量检索，开个副号走 `synthetic`——副号从第一天起就是这个身份，没有历史冲突，此时合成指纹完全合理，且不必把真机指纹落盘。

## 5. 降风险操作清单

1. **务必先跑 `xhs fp`**（`xhs doctor` 会显示当前模式）
2. **别用主号做批量**——风控惩罚落在账号上
3. `--throttle` 保持 ≥2.5s，别关 `--jitter`；不要 24h 匀速跑，模拟作息
4. 关注熔断日志（`XhsBlockedError`）；被熔断就停一段时间，别硬顶
5. `xsec_token` 会过期，详情报 `461/300031` 时重跑 `search` 段刷新
6. 别碰 `so.xiaohongshu.com`（对本出口 TLS 层已 RST）
7. 采到的数据自行评估合规边界
